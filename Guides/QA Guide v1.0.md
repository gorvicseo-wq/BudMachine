# QA Guide v1.0

Final Quality Assurance Standard for BudMachine Blog

## 1. Purpose

QA Guide — это финальный этап проверки статьи перед публикацией.
Он выполняется только после завершения всех предыдущих этапов:
- Editorial Guide
- SEO Guide
- Visual Prompt Guide
- Terminology Guide
- Anti-AI Checklist

Цель QA — убедиться, что статья полностью соответствует редакционным стандартам BudMachine и готова к публикации без дополнительных исправлений.

## 2. QA Workflow

Проверка всегда выполняется в одном и том же порядке.

```text
Draft
   │
   ▼
Structure QA
   │
   ▼
SEO QA
   │
   ▼
Editorial QA
   │
   ▼
Fact QA
   │
   ▼
Readability QA
   │
   ▼
Anti-AI QA
   │
   ▼
Visual QA
   │
   ▼
UX QA
   │
   ▼
Publication Ready
```

## 3. Structure QA

Проверяется общая архитектура статьи.

### Checklist

□ Есть Title  
□ Есть Description  
□ Есть H1  
□ Есть Introduction  
□ Есть минимум три H2 (или столько, сколько требуется теме)  
□ Есть Conclusion  
□ Нет пустых разделов  
□ Нет разделов из одного предложения  
□ Каждый H2 раскрывает отдельную тему  
□ Нет одинаковых H2  
□ Нет похожих по смыслу H2  
□ Разделы расположены в логичной последовательности  
□ После каждого H2 достаточно информации для полного раскрытия темы

## 4. SEO QA

Проверяется соответствие SEO Guide.

### Keyword Placement

□ Основной ключ присутствует в Title  
□ Основной ключ присутствует в Description  
□ Основной ключ присутствует в H1  
□ Основной ключ используется в первом абзаце  
□ Основной ключ присутствует минимум в одном H2  
□ Основной ключ присутствует в заключении

### Meta

□ Title имеет длину 45–60 символов  
□ Description содержит 140–160 символов  
□ H1 не дублирует Title полностью  
□ Длина H1 желательно не превышает 70 символов

### Internal Links

□ В статье размещены три контекстные внутренние ссылки  
□ Использованы разные естественные анкоры  
□ Внутренние ссылки органично встроены в текст  
□ После заключения добавлена ссылка на главную страницу блога с анкором наподобие «Больше интересных статей здесь»

### External Link

□ Добавлена одна авторитетная внешняя ссылка  
□ Используется rel="nofollow"  
□ Ссылка расположена ближе к началу статьи

### Images

□ Заполнен ALT  
□ Заполнен Image Title  
□ Имя файла оптимизировано под SEO

## 5. Editorial QA

Проверяется качество текста.

### Checklist

□ Нет повторения мыслей  
□ Нет повторения фактов  
□ Нет повторения примеров  
□ Нет повторения выводов  
□ Нет искусственного увеличения объема  
□ Каждый абзац несет новую информацию  
□ Каждый H2 отвечает на новый вопрос  
□ Нет логических противоречий  
□ Нет резких переходов между разделами  
□ Заключение действительно подводит итог, а не повторяет введение

## 6. Readability QA

Проверяется удобство чтения.

### Paragraphs

□ Абзацы не перегружены  
□ Размер абзацев различается  
□ Нет «стен текста»

### Sentences

□ Используется разная длина предложений  
□ Нет однотипных конструкций  
□ Нет монотонного ритма

### Lists

□ Используются только там, где действительно облегчают восприятие  
□ Не заменяют полноценное объяснение

### Tables

□ Используются только при необходимости  
□ Если таблица не добавляет ценности — она удаляется

## 7. Anti-AI QA

Финальная проверка естественности текста.

### Checklist

□ Нет шаблонных вступлений  
□ Нет шаблонных заключений  
□ Нет повторяющейся структуры H2  
□ Нет одинаковых конструкций предложений  
□ Нет злоупотребления вводными словами  
□ Нет частого использования «Кроме того»  
□ Нет частого использования «Также»  
□ Нет частого использования «Важно отметить»  
□ Нет частого использования «Следует учитывать»  
□ Нет ощущения машинной генерации  
□ Текст читается как написанный человеком

## 8. Fact QA

Проверка достоверности информации.

### Numbers

□ Все цифры перепроверены  
□ Нет противоречий  
□ Единицы измерения указаны корректно

### Facts

□ Нет недостоверных утверждений  
□ Нет выдуманных данных  
□ Все советы технически корректны

### Sources

□ Все источники существуют  
□ Использованы авторитетные источники  
□ Нет устаревшей информации

## 9. Visual QA

Проверка изображения.

### Image

□ Размер соответствует требованиям проекта  
□ Нет AI-артефактов  
□ Нет ошибок генерации  
□ Композиция сбалансирована  
□ Цветовая палитра соответствует стилю BudMachine

### Optimization

□ Формат JPEG/PNG  
□ Размер файла оптимизирован  
□ Изображение сохраняет хорошее качество после сжатия

## 10. UX QA

Финальная оценка статьи глазами читателя.

На каждый вопрос необходимо ответить «Да».

□ Пользователь сразу понимает тему статьи  
□ Ответ на поисковый запрос найден полностью  
□ Информацию легко найти  
□ Статья читается без усилий  
□ Нет ощущения затянутости  
□ Нет ощущения повторов  
□ Материал полезен на практике  
□ После прочтения у читателя не остается ключевых вопросов

## 11. Critical Errors (Stop Publish)

Наличие хотя бы одной из следующих ошибок автоматически запрещает публикацию.

### SEO

□ Отсутствует основной ключ в обязательных местах  
□ Нет Title  
□ Нет Description  
□ Нет H1  
□ Нет обязательных внутренних ссылок  
□ Нет ссылки на главную страницу блога после заключения

### Content

□ Обнаружены фактические ошибки  
□ Есть дублирование разделов  
□ Есть повторение одной мысли в разных местах  
□ Статья не отвечает поисковому запросу

### Anti-AI

□ Текст выглядит шаблонным  
□ Повторяются конструкции  
□ Повторяется структура разделов  
□ Статья читается как AI-генерация

### Visual

□ Отсутствует изображение  
□ Неверный размер изображения  
□ Есть AI-дефекты  
□ Изображение не соответствует фирменному стилю

## 12. Quality Score

Каждый раздел оценивается отдельно.

| Раздел | Баллы |
|---|---:|
| Structure | 10 |
| SEO | 10 |
| Editorial | 20 |
| Readability | 15 |
| Anti-AI | 15 |
| Facts | 15 |
| Visual | 5 |
| UX | 10 |
| **Итого** | **100** |

### Интерпретация

- **95–100 баллов** — Premium Quality, публикация без замечаний.
- **90–94 балла** — Отличное качество, допустимы только косметические правки.
- **80–89 баллов** — Требуется доработка.
- **Менее 80 баллов** — статья возвращается на переработку.

## 13. Error Catalog

Наиболее распространенные ошибки, выявляемые при QA.

### SEO

- Title длиннее рекомендуемого диапазона.
- H1 дублирует Title.
- Основной ключ используется слишком редко или слишком часто.
- Пропущена финальная ссылка на блог.

### Editorial

- Повторение одной мысли в нескольких разделах.
- Искусственное увеличение объема.
- Несколько H2 отвечают на один и тот же вопрос.
- Слабое заключение.

### Readability

- Слишком длинные абзацы.
- Одинаковая длина предложений.
- Избыточное количество списков.

### Anti-AI

- Повторяющиеся вводные конструкции.
- Механическая структура текста.
- Однообразный ритм.
- Шаблонные формулировки.

### Visual

- AI-артефакты.
- Несоответствие фирменному стилю.
- Некачественное сжатие изображения.
