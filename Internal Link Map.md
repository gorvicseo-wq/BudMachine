# BudMachine — Internal Link Map

## Назначение

Этот файл — рабочая база внутренней перелинковки BudMachine.

Он нужен, чтобы статьи не ссылались постоянно на одни и те же страницы, а формировали логичную тематическую сеть: информационные материалы, узкие практические статьи, проверки/инструкции и коммерческие страницы должны быть связаны между собой по смыслу.

Принцип: ссылка добавляется прежде всего ради пользователя и тематической связи, а не ради выполнения фиксированной квоты.

## Языковые каталоги

BudMachine имеет два самостоятельных языковых каталога:

- **RU:** `https://budmachine.com.ua/`
- **UA:** `https://budmachine.com.ua/ua/`

Любой URL с префиксом `/ua/` относится к украинской версии сайта.

### Правило языкового соответствия

- RU-статья по умолчанию ссылается на RU-страницы.
- UA-статья по умолчанию ссылается на UA-страницы.
- RU → UA и UA → RU не использовать без отдельной редакционной причины.
- При наличии тематически эквивалентных страниц на обоих языках выбирать страницу того же языка, что и статья.

## Правила ведения

Для каждой опубликованной или утверждённой статьи фиксировать:
- URL;
- язык;
- название;
- основной кластер/тему;
- тип страницы;
- исходящие внутренние ссылки;
- целевой URL каждой ссылки;
- фактический анкор;
- контекст/назначение ссылки;
- при необходимости — потенциальные будущие входящие ссылки.

При подготовке новой статьи:
1. проверить существующие страницы в этой карте;
2. искать релевантные страницы прежде всего в каталоге того же языка;
3. найти наиболее релевантные страницы с учётом тематического кластера;
4. проверить, какие URL уже получают много ссылок;
5. по возможности направить новую ссылку на релевантную страницу, которая пока недополучает внутренние ссылки;
6. не повторять одинаковые связки без необходимости;
7. после публикации обновить карту.

## Принципы распределения

- Не использовать один и тот же целевой URL как универсальную ссылку для каждой новой статьи.
- Не ставить несколько ссылок на одну страницу только ради количества.
- Важные страницы должны получать ссылки из нескольких релевантных материалов, но без искусственного массового повторения.
- Ссылки должны формировать тематические кластеры.
- Коммерческие страницы должны получать ссылки из материалов, где переход к услуге логичен для читателя.
- Анкоры должны быть описательными, естественными и соответствовать содержанию целевой страницы.
- Анкор не обязан дословно совпадать с SEO-ключом.
- Допустимы естественные словоформы и фразы из 2–4 слов, если они точнее описывают целевую страницу.

## Структура тематического кластера

Предпочтительная логика, если она соответствует сайту:

**Обзорная статья → узкая тематическая статья → практическая инструкция/проверка → коммерческая страница**

Это не обязательная схема для каждой темы. Использовать её только там, где она действительно отражает путь пользователя.

## Контроль баланса

Перед каждой новой статьёй проверить:

- Какие URL уже получают слишком много внутренних ссылок?
- Какие важные страницы получают мало ссылок?
- Не повторяется ли одна и та же пара страниц?
- Есть ли возможность связать материал с другим релевантным кластером?
- Не используется ли анкор только потому, что он является SEO-ключом?
- Действительно ли ссылка помогает читателю?
- Соответствует ли целевая страница языку статьи?

## Правило обновления карты

После утверждения или публикации новой статьи:

1. добавить её в реестр страниц;
2. записать все фактически использованные исходящие ссылки;
3. указать точные анкоры;
4. обновить количество входящих ссылок целевых страниц;
5. проверить баланс ссылок внутри соответствующего языкового и тематического кластера.

Google рекомендует использовать логичную структуру сайта, ссылаться на важные страницы из релевантных материалов и применять краткий описательный anchor text. Эти принципы используются как ориентир при ведении карты.
